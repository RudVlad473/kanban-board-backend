<objective>
Carry the board's `createdAt` through the nested `GET /boards/{boardId}/full` read, and close the
test hole that let it be missed.

Purpose: quick task 260825-dfd added `createdAt` to `BoardEntity` and to the flat
`BoardResponseDTO`, with the stated goal that it be "returned on every board response."
`BoardFullResponseDTO` — the one nested response, and the one a real client is most likely to use
as its single board fetch — was left out. A client reading `/full` today has to issue a second,
flat `GET /boards` purely to learn a timestamp the first response already had in hand.

Output: an `Instant createdAt` on `BoardFullResponseDTO` populated through the existing
`BoardFullMapper` by name-matching, an HTTP-boundary test proving the value arrives and equals the
flat representation's, and an extension to the existing flat-equivalence test so the board's own
fields are actually compared.

Scope guard (QUICK-04): no migration (`V8` already added the column), no entity change, no service
change, no mapper-interface change. If the work appears to need any of those, the auto-mapping
assumption was wrong — stop and record why rather than widening the change.
</objective>

<data_flow>
`BoardService.findFullById` verifies ownership through `findById`, then loads the whole board graph
via `BoardRepository.findByIdWithColumnsTasksAndSubtasks`, whose JPQL selects the root
`BoardEntity` itself — so `created_at` is already on the managed instance and no extra read is
needed. `BoardFullMapper.toBoardFullResponseDTO` then copies it onto the new DTO field purely by
name match, the same silent mechanism that already populates `id`, `name` and `version` (only
`column` → `columns` needs an explicit `@Mapping`, because those two names differ). Jackson
serializes the `Instant` to an ISO-8601 string through the JSR-310 module Spring Boot already
registers for every other endpoint, so the field appears in the HTTP body with no serializer
configuration anywhere.
</data_flow>
