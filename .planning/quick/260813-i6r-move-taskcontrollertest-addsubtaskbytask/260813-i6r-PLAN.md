<objective>
Move the blank-title boundary matrix for `SaveSubtaskRequestDTO.title` down from the controller tier
to the DTO/Bean-Validation tier, where `docs/CODE_STYLE.md` rule 4 says input-combination coverage
belongs.

Quick task 260813-h2f added `@NotBlank` to `SaveSubtaskRequestDTO.title` and, to prove it, added
four `TaskControllerTest.AddSubtaskByTaskId` tests that each vary only the `title` field across
blank-shaped JSON encodings (`{}`, `null`, whitespace-only, empty string) while asserting the same
collapsed validation envelope. A follow-up read-only triage of the whole suite found this is the
only place in the codebase where a controller test enumerates a DTO's validation boundary matrix
instead of proving an HTTP contract — everywhere else already sits at the right altitude.

Purpose: keep the coverage, drop the altitude error, and leave one clean worked example of the
rule-4 split on the endpoint that motivated it.
Output: 3 tests deleted from `TaskControllerTest`, 3 equivalent tests added to
`SubtaskTitleMessageTest.SaveSubtaskRequestDTOTest`, net test count unchanged at 444.
</objective>

## Approach & Trade-offs

**Decisions locked for this task** (derived from the task description's constraints):

- **D-01** — Keep `whenJsonBodyIsEmpty` (`{}`) as the single controller-tier representative; delete
  `whenTitleIsNull`, `whenTitleIsWhitespaceOnly`, `whenTitleIsEmptyString`. Rationale: `{}` is the
  case that originally produced the 409 raw-NOT-NULL leak 260813-h2f fixed, so it is the real HTTP
  regression guard; and at the DTO tier `{}` and `{"title":null}` are the same object (`title ==
  null`), so keeping the JSON-null variant at the controller would be duplication of a duplication.
- **D-02** — The moved cases land in `SubtaskTitleMessageTest`'s existing `SaveSubtaskRequestDTOTest`
  nested class, reusing that file's exact harness (field `Validator` built in `@BeforeEach`, a
  private title-shaping helper alongside `overLongTitle()`, `hasSize(1)` + message equality,
  lowercase `// arrange` / `// act` / `// assert` markers). No new testing style is invented.
- **D-03** — The empty-string case asserts on the *set of triggered constraint annotation types*
  (`NotBlank` + `SubtaskTitle`), not on `hasSize(1)` + message. Forced, not preferred: `""` trips
  both `@NotBlank` and `@SubtaskTitle`'s `@Size(min=3)`, so the file's existing `hasSize(1)` shape
  is arithmetically false for this input, and both violations render the *same* message string —
  message equality alone cannot distinguish empty-string from whitespace-only and would silently
  make the two new tests assert the same thing.
- **D-04** — Add before delete; `UpdateSubtaskRequestDTOTest` and `docs/CODE_STYLE.md` stay
  byte-identical. Rule 4 as written already governs this move; do not expand it.

**Alternates considered:**

| Approach | Pros / Cons | Why picked / rejected |
|---|---|---|
| **A. Move to DTO tier, one representative kept at controller** (chosen) | + Each tier asserts the question it owns: HTTP envelope once, validation matrix N times where it is cheap. + The 3 DTO tests are pure unit tests (no Spring context, no Testcontainers) — seconds instead of a MockMvc round trip each. − The `{}` / `null` distinction stops being observed at the HTTP tier; only the DTO-tier null case remains. | Picked. The lost distinction is not a real one: Jackson deserializes both to `title == null`, so the controller was never observing two different states. |
| **B. It would relocate the tests to a tier where the property under test does not exist. |
| **C. Leave the four controller tests, add nothing** | + Zero risk, zero work. − Leaves the one place in the suite that contradicts rule 4, and leaves a 4-MockMvc-request-per-run cost for coverage a validator harness gives in milliseconds. | Rejected — this is the finding the task exists to close. |
| **D. Mitigated instead by widening the destination file's class Javadoc in Task 1. |

**Non-obvious trade-offs:**

- *Message collision is the real hazard here, not the move.* `@ReportAsSingleViolation` on
  `SubtaskTitle` collapses its inner `@Size` onto `SubtaskTitle`'s own default message, which is the
  byte-identical string `@NotBlank` uses on the same field. Three different inputs failing three
  different ways all render `"Subtask title cannot be empty"`. A naive copy of the existing
  assertion pattern would therefore produce three green tests that no longer distinguish anything —
  green, passing, and worthless. D-03 exists solely to prevent that.
- *Runtime:* strictly negative. 3 MockMvc POSTs (full security filter chain + JPA + Postgres
  container) are replaced by 3 in-JVM `Validator.validate()` calls. No new Spring context is
  created — `SubtaskTitleMessageTest` extends none of the `AbstractApp*` bases and starts no
  container.
- *Security:* the endpoint's actual behavior does not change; this is test-only. The risk is a
  silent *coverage* regression re-opening the blank-title path 260813-h2f closed. That is why the
  plan does not accept "tests are green" as proof — Task 1 falsifies against production code.
- *Not applicable:* no package-manager installs, no dependency changes, no `src/main` change in the
  committed diff.
