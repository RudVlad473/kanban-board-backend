## Accomplishments

- **D-01 decision, recorded as resolved:** the user selected `promote-five` (Approach B) before this execution began. Rationale carried forward from the plan's `<measured_ground_truth>`: planning measured that removing `allErrorsAsWarnings = true` alone is a no-op against the 27 findings, since all 27 are WARNING severity by default and the demotion flag only downgrades ERROR-severity checks. Only promoting the five triaged checks (`FutureReturnValueIgnored`, `StringCaseLocaleUsage`, `MissingOverride`, `NotJavadoc`, `DefaultCharset`) to ERROR makes "hard-gate" a true statement.
- **Task 2 (tracer):** fixed the one finding with genuine behavioral risk first — `ActivityLogIdempotencyE2ETest`'s `DefaultCharset` site now decodes Kafka dead-letter bytes explicitly as UTF-8 instead of the platform default, closing a false-green risk in a negative assertion. Rewrote the `build.gradle` Error Prone comment block to describe measured reality instead of a stale 27-finding claim, and removed the `compileTestJava` severity demotion. Verified: 26 remaining warnings (27 minus the fix), `BUILD SUCCESSFUL`, `fastTest` green.
- **Task 3 (auto), by group:**
  - **MissingOverride (3, fixed):** added `@Override` to `AbstractAppE2ETest`, `AuthenticationControllerTest`, and `UserServiceTest`'s `setup()` fixture hooks — purely additive, guards against a silent orphaned fixture on a future rename of `AbstractAppTest.setup()`.
  - **NotJavadoc (1, fixed):** changed `AbstractKafkaContainerTest`'s API-version-pin comment from a Javadoc opener (`/**`) to a plain block comment (`/*`) — it documents a `static` initializer, which Javadoc cannot attach to. Comment text preserved verbatim per the plan's constraint (it is cited by `docs/CODE_STYLE.md` rule 8).
  - **StringCaseLocaleUsage (4, fixed):** pinned `Locale.ROOT` on all four `toLowerCase`/`toUpperCase` calls in `SignupRequestDTOTest`'s password fixtures, with a comment explaining that a Turkish default locale's dotted/dotless-I mapping would otherwise corrupt the "no uppercase"/"no lowercase" validation fixtures those calls build.
  - **FutureReturnValueIgnored on Kafka sends (16, fixed):** added `AbstractKafkaContainerTest.sendAndAwaitAck(ActivityEvent)` — a protected helper that derives the send key from the event's own `eventId`, sends to `KafkaTopics.ACTIVITY`, and blocks on the ack with an explicit 30-second timeout matching the class's existing `@TestPropertySource` producer bounds. Routed all 16 call sites through it across `ActivityLogConsumerE2ETest` (11), `ActivityLogDeadLetterE2ETest` (2), and `ActivityLogIdempotencyE2ETest` (3), removing the now-redundant per-class `@Autowired KafkaTemplate` fields and 16 duplicated `event.eventId().toString()` expressions. Test methods that now call the helper declare `throws Exception`.
  - **FutureReturnValueIgnored on executor.submit (2, deliberately dropped, documented):** left `ActivityLogIdempotencyE2ETest`'s concurrency race test's two `executor.submit` calls fire-and-forget on purpose — awaiting either future would serialize the two threads and destroy the race window the test exists to open. Each is assigned to a **block-scoped** `Future<?> unused` local (each submit wrapped in its own `{ }` block) with a comment explaining the reasoning; block-scoping was necessary because Error Prone's suggested fix matches on the literal name `unused`, and two locals both named `unused` in the same method scope is a compile error. Confirmed empirically that the explicit `Future<?> unused` form (not `var unused`) satisfies the check, so no fallback to the `KafkaEventPublisher` `var unused` precedent was needed — both this rule and `docs/CODE_STYLE.md` rule 9 (`var` only when the RHS type is obvious) are satisfied simultaneously.
  - **Group 6 (D-01 applied):** added `options.errorprone.error('FutureReturnValueIgnored', 'StringCaseLocaleUsage', 'MissingOverride', 'NotJavadoc', 'DefaultCharset')` to `compileTestJava` in `build.gradle`, with a comment explaining the asymmetry with `compileJava` (which carries no such promotion and still has one unfixed warning-severity `EscapedEntity` finding at `UserMapper.java:23`, out of scope here).
  - **Group 7 (todo closed):** moved the source todo to `completed/` with its Solution section's incorrect premise corrected — the archived record now states plainly that removing the demotion alone was a measured no-op and that the ERROR promotion was the step that actually closed the gap.
- **Teeth check (verification item 6):** temporarily dropped `Locale.ROOT` from one `SignupRequestDTOTest` call, ran `./gradlew compileTestJava` — it FAILED, naming `[StringCaseLocaleUsage]` as an `error` (not a warning). Reverted; re-ran — `BUILD SUCCESSFUL`. Proves the promotion has real effect, not just configured-but-inert.
