never transferred four of the six repo-relative bind-mount sources `docker-compose.prod.yml`

paths; the new gate makes the two lists provably agree at pull-request time instead of by memory.

**Approach A — extend `source:` with the four explicit paths, and add a CI coverage gate. CHOSEN.**
One line changes in `deploy.yml`; a new `scripts/verify-deploy-scp-coverage.py` + self-test proves
the two lists agree, wired into `invariant-checks.yml` as a third job.

**Approach B — extend `source:` only, no gate.** The literal brief. Ships the fix and nothing else.

## Non-obvious trade-offs

**1. Deletion is not synced, and this fix does not change that.** `rm:` is deliberately absent (it
would destroy `.env.prod`). `appleboy/scp-action` extracts its tar over the target: files are
created and overwritten, never removed. So a dashboard JSON **deleted** from the repo lingers on the
VM, and Grafana's file provider (`updateIntervalSeconds: 30`) keeps serving the orphan indefinitely.
Bounded and one-directional — new and changed content always wins — but it must be documented rather
than discovered later. Not closable here without the forbidden `rm:`.

**2. Copying the file is not the same as applying it, for three of the four.** A bind-mounted
file's *content* is not part of Compose's config hash, so `up -d` does not recreate these containers
— the same mechanism `deploy-to-netcup`'s own Caddy comment already documents at length. Per
consumer:
- **Grafana dashboards** — hot. The file provider re-reads `json/` every 30s, so dashboard changes
  do land automatically once the files arrive. *This is the case the brief cares about, and it is
  fully closed by this fix.*
- **Grafana datasources** — provisioned at startup only; a `datasources.yaml` edit needs a container
  restart.
- **Prometheus / Loki / Promtail** — config read at process start; need a restart or SIGHUP.

So this task makes the *files* current in every case and the *running config* current in one.
Closing the rest means adding reload steps to the `deploy-to-netcup` SSH script — explicitly
out of bounds for this task. Task 3 files it as a todo rather than silently implying it is covered.

**3. Security.** The change widens what CI writes into a production directory from three enumerated
paths to seven. All four additions are non-secret, committed configuration; no credential surface,
no new secret, no new action, no `target:` change, no `rm:`. The gate itself reads only committed
files, reaching no network and no registry — the property `invariant-checks.yml` requires of a
blocking per-PR job.

**4. Performance.** ~590 KB added per deploy, 578 KB of which is the three vendored dashboard JSONs.
Negligible against the image pull that dominates this job, and the transfer is over an already-open
SSH connection.
