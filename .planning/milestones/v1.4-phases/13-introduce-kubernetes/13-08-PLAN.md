**Derivation (write it into each Middleware as a decision-record comment, dated).** Traefik's bucket starts full at `burst` and refills `average` tokens per `period`. The worst-case number of accepted requests from one client in any window W is therefore `burst + average × W / period`.

Choose integer `(average, period, burst)` per zone so that this worst case over Caddy's window is ≤ Caddy's budget, and `burst` is still large enough for a legitimate retry burst:
- auth: W = 5m, budget 20 — e.g. burst 10, average 10, period 5m;
- general: W = 1m, budget 120 — e.g. burst 60, average 60, period 1m;
- grafana_login: same shape as auth.

Keep `sourceCriterion.ipStrategy` keyed on the direct client address, with `ipv6Subnet: 56` if 13-04 kept it. Remove the provisional labels; each comment states the bound and its arithmetic.

**infra/vm/k3s-host-firewall.sh** (`apply|check|remove`), headed like docker-user-firewall.sh (WHY / what it does not cover / dated):
- Chain `KANBAN-INGRESS` in the `mangle` table, jumped from `PREROUTING` at position 1 for `-i eth0`. It runs before nat DNAT, which is why it covers NodePorts and hostPorts that INPUT never sees.
- Rules, in order:
  1. `RETURN` for conntrack ESTABLISHED,RELATED;
  2. `RETURN` for NEW tcp to the Layer 1 allow-list (22, 80, 443 — read from the live `iptables -S INPUT` in Task 1 and hard-coded, with a comment);
  3. `RETURN` for icmp;
  4. `DROP` for every other NEW packet;
  5. final `RETURN`.
- `apply` is idempotent: it flushes and rebuilds the chain.
- `apply --dead-man <minutes>` schedules `remove` via `systemd-run --on-active`.
- `check` asserts the chain exists, the jump is at PREROUTING position 1, and the rules match; exit 1 with a named diff otherwise.
- IPv4 only; the header says why: k3s is single-stack, and the IPv6 exposure todo is re-evaluated in 13-10 when Docker stops.

**infra/vm/k3s-host-firewall.service:** `Type=oneshot`, `RemainAfterExit=yes`, `ExecStart=… apply`, `ExecStop=… remove`, `After=network-online.target`, `Wants=network-online.target`, `WantedBy=multi-user.target`. It needs no ordering against docker or k3s: neither touches mangle PREROUTING. The header records that as an observation, checked in this task with `iptables -t mangle -S PREROUTING` before and after `systemctl restart k3s`.

**Install (VM):**
1. Copy the files. `apply --dead-man 10`.
2. From a **new** SSH session, confirm login works, then cancel the dead-man timer.
3. `systemctl enable --now k3s-host-firewall`. Run `check`.
4. `systemctl restart k3s`, then run `check` again: the jump is still at position 1.
