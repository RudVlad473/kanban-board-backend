## Accomplishments

- **Task 1 (checkpoint, resolved prior to this resume):** Human operator selected **option-a** — approve the V1-V4 migration-history split exactly as researched. `V1__init.sql` reconstructs the pre-Epic-2 baseline; V2 (optimistic locking `version` columns), V3 (`activity_log` table), V4 (`password_hash NOT NULL`) are reserved for the next plan(s), one migration per existing manual DDL script, in the order they were actually applied.
- **Task 2:** All three layers wired in one slice:
  - `build.gradle` — added `org.flywaydb:flyway-core` and `org.flywaydb:flyway-database-postgresql` as unversioned `implementation` dependencies immediately after `org.postgresql:postgresql`, with a comment explaining the deliberate BOM-managed version omission.
  - `src/main/resources/application-test.properties` — added `spring.flyway.enabled=false` inside the existing `# === hibernate ===` section, directly above the unchanged `ddl-auto=create-drop` line, with a comment explaining why this addition is required and orthogonal to D-04.

- **Entity cross-check performed before applying:** confirmed exactly six `@Entity` classes in `src/main/java/com/vrudenko/kanban_board/entity/` (`UserEntity`, `BoardEntity`, `ColumnEntity`, `TaskEntity`, `SubtaskEntity`, `ActivityLogEntity`) — no uncovered seventh entity or schema delta found, so Task 1's approved split needed no adjustment.
- **Proven end-to-end:** `docker compose down -v` (wiped the accumulated `postgres-data` volume with months of `ddl-auto=update` dev-session schema and no `flyway_schema_history`), then `docker compose up -d --build`. App logged `Started KanbanBoardApplication in 30.725 seconds`. `SELECT version, script, success FROM flyway_schema_history ORDER BY installed_rank` against the compose Postgres returned exactly one row: `1|V1__init.sql|t`.
- `./gradlew spotlessCheck fastTest` — `BUILD SUCCESSFUL`, confirming `flyway-core` on the classpath does not break any `@SpringBootTest` running against H2.

This is Hibernate's still-active `ddl-auto=update` (docker-compose's `SPRING_JPA_HIBERNATE_DDL_AUTO: update` env override) attempting to reconcile a constraint that doesn't exist in the V1-only schema yet — expected and harmless per RESEARCH.md's Pitfall 2 and this task's own note that the `update` override is unchanged in this plan (Plan 03's job). Not a Flyway error; `flyway_schema_history` shows the migration succeeded regardless.
