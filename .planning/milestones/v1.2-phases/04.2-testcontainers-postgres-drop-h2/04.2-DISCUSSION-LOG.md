## Test isolation

| Option | Description | Selected |
|--------|-------------|----------|
| Keep `@AfterEach deleteAll()` as-is | Isolation already doesn't depend on `create-drop`; genuine no-op | ✓ (on re-ask) |
| `@Transactional` rollback per test | Faster, bulletproof isolation | ✗ (initially chosen, then reversed) |
| Truncate all tables between tests | Explicit and complete; adds a maintained table list and per-test cost | |

**User's choice:** Initially `@Transactional` rollback; reversed to `deleteAll()` after evidence was presented.
**Notes:** Rollback was flagged as conflicting when first offered, then verified against the code before re-asking rather than asserted. Three confirmed conflicts: (1) `RecordingActivityEventListener` and `KafkaEventPublisher` are both `AFTER_COMMIT`, so rollback discards held events and the assertions fail on an empty list; (2) `countQueries()`/`getPrepareStatementCount()` is defeated by a shared persistence context caching fixtures; (3) `AbstractAppE2ETest` drives a real server over HTTP, so a test-thread transaction never spans the request. None are Postgres-specific — all are true on H2 today.

User asked a clarifying question ("what is commit in this context?") before deciding; answered in terms of this codebase's after-commit publishing guarantee, then the choice was made. Became D-02, with D-02a filed as the follow-on gap: rows unreachable from a `UserEntity` (notably `activity_log`) need verified cleanup now that the schema is no longer dropped per context.
