# Phase 07.1 Plan 07: Retarget fastTest to @Tag-based selection Summary

**Pre-commit gate membership is now an explicit per-class `@Tag` declaration instead of an emergent property of class naming — closes the exact coupling that made Phase 7's test-tier downgrade unable to rename its own classes safely.**

## Performance

- **Duration:** ~195 min across two sessions (this session resumed from a Wave 5 interruption where Task 1 was staged but uncommitted)
- **Started:** 2026-08-09 (prior session, Task 1 staged)
- **Completed:** 2026-08-10T10:16:00Z
- **Tasks:** 3
- **Files modified:** 25 (14 in Task 1, 15 in Task 2 with overlap, 4 in Task 3)

## Accomplishments

- `fastTest`'s selection mechanism replaced: `filter { excludeTestsMatching '*E2ETest' }` → `useJUnitPlatform { excludeTags 'kafka', 'realSocket' }`, matching the `rehearsal` tag precedent already used by the `test` task
- 8 Kafka-backed `activitylog/` classes tagged `@Tag("kafka")`, `BoardCreationE2ETest` tagged `@Tag("realSocket")`, `HistoricalSchemaRehearsalE2ETest` carries both `rehearsal` and `kafka`
- 11 in-process MockMvc-tier classes renamed to drop the misleading `E2ETest` suffix (safe now that gate membership is tag-driven, not name-driven)
- `UserAuthenticationProvider.java`'s stale security-enforcement comment fixed (was citing a class deleted in Phase 7, now cites the real, verified `AuthenticationTest.SigninPersistence#shouldNotPersistBcryptHash_whenSigninSucceeds`)
- Falsification check proved the `@Tag`/`excludeTags` mechanism actually selects rather than merely compiles: temporarily tagging an 18-test class dropped `fastTest`'s count from 266 to 248 exactly, and removing the tag restored 266

**1. [Rule 3 - Blocking] Fixed a pre-existing `BoardServiceTest$FindFullByIdQueryCountTest` DataFactory name-collision flake**
- **Found during:** Task 1's verification pass
- **Issue:** `buildBoardGraph` called `dataFactory.getRandomWord` twice per test for the same user; the bundled word list's small pool of short filler words produces real duplicate draws, tripping the per-user board-name unique constraint

- **Files modified:** `src/test/java/com/vrudenko/kanban_board/service/BoardServiceTest.java`
- **Verification:** Reproduced 4 consecutive times inside the unbypassable pre-commit hook before escalating; fix verified across multiple full-suite runs afterward
- **Committed in:** `0c7a86e` (Task 1 commit)
