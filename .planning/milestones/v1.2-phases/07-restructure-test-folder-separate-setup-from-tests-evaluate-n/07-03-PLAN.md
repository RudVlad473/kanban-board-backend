<tradeoffs>
## Approach considered A — authenticate with an injected pre-authenticated principal, as the four existing controller tests do

## Approach considered B — authenticate with a real signin POST and session-cookie relay — CHOSEN

## Approach considered C — leave both classes on the real-socket tier

| Approach | Pros / Cons | Why picked / rejected |
|----------|-------------|-----------------------|
| A — injected principal | Pro: shortest diff, matches the four existing controller tests, marginally faster per test. Con: changes what each test proves — the authentication path stops being exercised — and requires a per-class judgment call about whether that matters, which is exactly the judgment that goes wrong at scale across 12 files | Rejected as the phase-wide default. Every downgrade candidate currently signs in for real; keeping that makes the conversion a mechanical translation instead of a semantic rewrite |
| B — real signin + cookie relay | Pro: one-for-one translation of the existing code, so a reviewer can diff intent rather than re-derive it; structurally immune to RESEARCH.md's Pitfall 2; one idiom across all 12 downgraded classes. Con: one extra request per test, and diverges from the four existing controller tests' idiom | **Picked.** Fidelity beats brevity on a refactor whose whole risk is silently changing what tests prove |
| C — no downgrade | Pro: zero risk. Con: leaves D-03 unexecuted for two classes that provably need no socket | Rejected per D-03 and D-04 |

**Non-obvious trade-offs:**
- **The `/api` context path silently disappears.** The real-HTTP fixture base sets RestAssured's base
  path from `server.servlet.context-path`. MockMvc does not apply that property at all, so converted
  URLs are the bare `ApiPaths` constants. A converted request that keeps the prefix will 404 in a way
  that looks like a routing bug rather than a conversion bug.
- **Ordering assertions are not concurrency assertions.** `ColumnOrderingE2ETest` exercises an
  ordering invariant, which reads like a race but is not one — every operation in it is issued and
  awaited sequentially. That is precisely why it qualifies for downgrade while `BoardCreationE2ETest`
  does not.
- **Cascade-deletion assertions read state, not responses.** `ColumnDeletionE2ETest` proves the
  cascade by querying repositories after the delete. Those assertions are dispatch-mechanism-agnostic
  and must be carried across untouched; do not "improve" them into response-body assertions.
</tradeoffs>
