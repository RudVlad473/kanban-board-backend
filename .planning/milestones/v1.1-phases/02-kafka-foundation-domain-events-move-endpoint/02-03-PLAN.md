    shows, but those tutorials target the JVM `apache/kafka` image; `apache/kafka-native`'s
    runtime layer is a bare alpine with only `gcompat` and `bash` installed and no JVM or
    `bin/` script tree at all, so such a probe fails every attempt with a file-not-found error
    and the service never goes healthy. Set `interval: 5s`, `timeout: 5s`, `retries: 8`,

    D-03's 30-60 second guidance. Add a YAML comment directly above the healthcheck recording

    socket proves the listener accepts connections, not that KRaft controller election has
    settled, which is what `start_period` plus multiple retries is compensating for.
