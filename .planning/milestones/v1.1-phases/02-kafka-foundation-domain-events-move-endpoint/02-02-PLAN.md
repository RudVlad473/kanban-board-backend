<objective>
Expand the proven tracer path to the four remaining mutation types. Plan 01 established the
architecture — sealed `ActivityEvent` contract, `ApplicationEventPublisher` at the tail of a
mutating service method, `@TransactionalEventListener(AFTER_COMMIT)` owning the Kafka send.
This plan repeats that shape for task creation, task deletion, board creation and column
creation, and closes the implicit ambient-transaction dependency that would otherwise let an
event silently vanish.

Purpose: EVENT-01 asks for five typed records and EVENT-02 asks all three domain services to
publish. Plan 01 delivered one of each; this plan delivers the rest and proves the negative
cases (rollback publishes nothing, updates publish nothing) that make "no ghost events, no
dropped events" a tested property rather than a claim.

Output: four new event records, a widened sealed `permits` clause, publish calls in
`TaskService`/`BoardService`/`ColumnService`, `@Transactional` on the three `save` methods,
and an after-commit publication test covering all five event types plus rollback suppression.
</objective>
