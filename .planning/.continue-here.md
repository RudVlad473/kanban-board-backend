## The four confirmed defects (all reproduced by execution, all re-verified independently)

- **D1 — `@Pattern.flags()` silently discarded.** `contribute()` reads `pattern.regexp()` and never
  `pattern.flags()`. `@OptionalNotBlank` is `@Pattern(regexp = ".*\\S.*", flags = Pattern.Flag.DOTALL)`
  and its own Javadoc says DOTALL is required. Two proven symptoms: a multi-line title the server
  accepts is rejected by the published pattern under full-match; and Java's `\s` is ASCII-only while
  ECMA-262's is Unicode, so three NBSP characters are accepted by the server and rejected by the
  document. **Live defect, highest priority.** Fix rule: fail closed — publish a pattern only where
  Java→ECMA equivalence is proven by a test, otherwise publish none.
- **D2 — the phase-2 reassert LOOSENS.** In `Accumulator.applyTo`, `setMinLength`/`setMaxLength`/
  `setPattern` are unconditional while `format`/`example`/`description` are `== null`-guarded. Phase 1
  seeds from the schema so unconditional is safe there; phase 2 replays a stale snapshot onto the
  final document and overwrites anything set in between. The "Never loosen" comment is false. Latent
  today (no DTO field carries `@Schema`) — but this change introduces `@Schema` to the vocabulary.
  Fix: split into `applyTo` (phase 1) and a tighten-only `reassertOn` (phase 2).
- **D3 — `@Size` counts UTF-16 code units, JSON Schema counts code points.** 17 `😀` is Java length 34
  and 17 code points, so `@SubtaskTitle(max=32)` rejects it while published `maxLength: 32` accepts —
  document looser than enforcer. No exact representation exists; needs a judgement call plus a dated,
  falsifiable decision comment. **Do NOT change server validation to count code points** — that is a
  behavior change disguised as a documentation change.
- **D4 — internal tooling note leaked into the public API document.** `Password`'s `@Schema`
  description is published on both password properties and discloses that the repo runs a gitleaks
  pre-commit scan and what it matches. Truncate at "…one special character."; move the rationale to a
  `//` comment.

Plus five cheap secondary findings (assert HTTP 200 in `fetchDocument()`; two false claims in the
`EquivalenceWithRealValidator` Javadoc; a mutation-blind `description` branch; a backreference
renumbering guard). Full detail is in the fixer's brief and in `.planning/HANDOFF.json`.
