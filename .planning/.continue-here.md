# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Manual root-SSH SCP into `/opt/deploy/kanban-board-backend/` corrupts the next automated deploy — files land owned by `root:root`, but the CI deploy user is `deploy`, and `appleboy/scp-action`'s tar extraction cannot overwrite a file it does not own (`tar: ...: Cannot open: File exists`). This happened for real this session and broke `deploy-to-netcup` on the very next push. Structural mitigation: never SCP as `root` into that directory as an "unblock"; if a one-off VM fix is truly needed, `chown -R deploy:deploy` the touched paths immediately afterward, or find the `deploy` user's own key instead.
- [ ] CONSTRAINT: Grafana's public-dashboard feature reads the dashboard's SAVED "current" variable value, not whatever a browser URL happens to show. Visiting the dashboard and letting Grafana auto-populate a `var-X=...` query param is NOT the same as it being saved — confirmed live: Postgres Internals' public link is currently broken (every panel errors, one gauge shows 9795%) because `Instance`/`Database` were never explicitly selected-and-Saved, even though the interactive browser view looked fine.

**Do not proceed until both boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Root-owned files block CI deploy | Manual `scp` as root into the VM's deploy directory silently breaks the next `appleboy/scp-action` run | blocking | Always `chown -R deploy:deploy` after any manual root-SSH file placement into `/opt/deploy/kanban-board-backend/`, or avoid manual SCP entirely and push through CI |
| Public-dashboard variable freeze is save-gated, not view-gated | A dashboard "looking right" in an authenticated browser tab proves nothing about what the public link serves | blocking | Before trusting a public link, always independently `curl` its `/api/public/dashboards/<token>` and check `templating.list[].current` is non-empty, or load the actual public URL fresh (no session, no URL query params) |
| Pasting a Grafana credential into chat | Happened again this session (viewer password pasted in plaintext) despite an existing open todo tracking the same incident for a different credential | advisory | Prefer having the human drive admin-only actions themselves rather than handing credentials to the agent when avoidable; if handed over anyway, recommend rotation afterward |
