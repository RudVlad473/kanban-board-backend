## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Worktree pre-dispatch-commit step silently excluded | `init.quick`'s `section_manifest` excluded `worktree-pre-dispatch-commit` for a `--discuss`-mode run even though `USE_WORKTREES=true`. If skipped, the executor's freshly-forked worktree (forks from `origin/HEAD`, not local HEAD) cannot see an uncommitted `PLAN.md`/`CONTEXT.md`. | advisory | Before dispatching a worktree-isolated executor, check whether `PLAN.md`/`CONTEXT.md` are committed. If not, manually run the `worktree-pre-dispatch-commit.md` step's bash block (commit them, capture the resulting SHA as `QUICK_PLAN_COMMIT`) regardless of what `section_manifest` says, then push to origin before dispatch so the fork base is current. |
| Bash shell cwd sticks across tool calls | A `cd` into a worktree path (to inspect it) persisted as the shell's cwd for every later `Bash` call in the same turn, which then caused a `Write` tool path-guard error ("resolves to git root X which differs from active worktree root Y") when writing to the main tree. | advisory | After any inspection command that `cd`s into a worktree or subdirectory, explicitly `cd` back to the main repo root before the next file-writing tool call. |
| `worktree.cleanup-wave` blocks on ANY uncommitted change, including intentional ones | The executor was correctly instructed not to commit `STATE.md`/`SUMMARY.md` (orchestrator's job). That left the worktree "dirty," and `cleanup-wave` refused to merge until it was clean. | advisory | Before calling `cleanup-wave`: read/copy out any uncommitted docs content left in the worktree, then `git checkout -- <file>` (tracked) / `rm` (untracked) to make the worktree clean, and re-apply those docs edits to the main tree afterward as the orchestrator's own Step 7/8. |
| `cleanup-wave` can report "blocked" after actually succeeding | One `cleanup-wave` call reported `worktree_remove_failed` / `blocked`, but `git log`/`git worktree list` showed the merge and removal had already succeeded — the reported failure was noise from a redundant removal attempt. | advisory | Don't trust a "blocked" cleanup-wave status literally — verify with `git worktree list` and `git log --oneline` before assuming the merge didn't happen or retrying destructively. |
| Concurrent `./gradlew --stop` kills an in-flight commit's pre-commit hook | The executor's own SUMMARY.md documented this: a backgrounded `git commit` (running `spotlessCheck`+`fastTest` via the hook) was killed by an unrelated `./gradlew --stop` call, leaving a stale Gradle daemon file lock on retry. | advisory | Never run `./gradlew --stop` while another gradle invocation (including one inside a git hook) may still be executing. Run commits in the foreground with a generous timeout instead of backgrounding + racing them. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
