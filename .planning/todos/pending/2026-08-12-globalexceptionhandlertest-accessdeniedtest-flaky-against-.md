## Problem

`AccessDeniedTest.shouldReturnForbiddenWithAccessDeniedCode_andDiscloseNothing_whenBoardOwnedByAnotherUser`
intermittently fails (observed twice during quick task 260812-eg8's own pre-commit gate retries,
unrelated to that task's changes):

```
Expecting actual:
  "{"type":"about:blank","title":"Forbidden","status":403,"detail":"...","instance":"...","code":"ACCESS_DENIED"}"
not to contain:
  "about"
```

The test asserts the response body does not leak the other user's board name via
`Assertions.assertThat(response.getContentAsString()).doesNotContain(otherBoard.getName())`. The
board name is generated by `dataFactory.getRandomWord(...)`, which occasionally produces the word
`"about"` (or a name containing it as a substring). Every `ProblemDetail` response from Spring's
default RFC 7807 serialization carries the literal `"type":"about:blank"` field, so on the unlucky
draw the assertion fails against that unrelated boilerplate field, not against an actual data leak.
Confirmed in isolation (`./gradlew test --tests GlobalExceptionHandlerTest`) that the test passes
reliably absent an unlucky random word — this is test flakiness, not a production defect.

## Solution

Scope the assertion to a value that cannot collide with RFC 7807 boilerplate, e.g. assert
`otherBoard.getName()` does not appear in the `detail` field specifically
(`objectMapper.readTree(response.getContentAsString()).get("detail").asText()`) rather than the
raw response body string. Verify the fix by temporarily forcing `dataFactory.getRandomWord(...)`
(or an equivalent seam) to return `"about"` and confirming the test still passes correctly instead
of failing on the boilerplate collision.
