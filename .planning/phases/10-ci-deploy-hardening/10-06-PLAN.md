## Non-obvious trade-offs

- **Sequencing (why this is wave 3 and not wave 1):** the README must describe the CI gates that
  actually exist. Three of the five preceding plans end in a blocking human checkpoint, and one of
  those (plan 10-04, Task 3) offers an explicit revert path for the dependency-verification metadata.
  Writing this README before those checkpoints resolve risks shipping a front door that advertises a
  control the repository does not have — the single worst defect class for a document whose entire
  purpose is to be believed on sight.
- **Maintenance (real, recurring):** an embedded Mermaid block is a *copy* of
  `docs/diagrams/infra-physical-deployment.mmd`. The two will drift unless someone updates both. The
  alternative — linking the rendered `.png` — avoids drift but loses GitHub's native rendering and
  the theme-adaptive vector output D-02 chose deliberately. Accepted, with the mitigation that the
  README block cites its source file by path so a reader (and a future editor) knows where the
  canonical version lives.
- **Rendering risk (must be checked, not assumed):** `infra-physical-deployment.mmd` uses a
  `%%{init: ...}%%` directive, nested `subgraph` blocks, an invisible-link (`~~~`) spacer, and inline
  `style` statements. GitHub's Mermaid version is not the local CLI's. If any construct fails to
  render, the README shows a raw error block — strictly worse than no diagram. This must be verified
  on GitHub itself, not in a local preview.
- **Accuracy drift (specific, checkable):** the current README asserts a precise test-method count
  and describes the security gates as gitleaks plus a report-only OWASP scan. Plan 10-05 added a test
  class; plans 10-02 and 10-04 added gates. Both claims are stale the moment this phase lands and
  must be re-derived from the repository rather than edited by guess.
- **Audience tension:** HARDEN-08's newcomer wants orientation; a returning contributor wants the
  API table and the local-dev commands near the top. D-03 settles it in the newcomer's favour, and
  scannable headings plus the preserved API table keep the contributor's path to two seconds of
  scrolling rather than a lost section.
</tradeoffs>
