## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Task-notification `killed`/`failed` status can be flatly wrong for long-running poll loops | The Oracle capacity poller (a `while true` + `sleep` bash loop) got a harness `<task-notification>` reporting `status: killed` twice this session while the actual OS process was still alive and actively polling — confirmed both times via direct process-tree inspection (parent/child lineage, creation timestamps, log line growth). Blindly trusting the first false report led to briefly running two duplicate poller instances against Oracle's API simultaneously. | blocking | Before relaunching anything in response to an unexpected `killed`/`failed` notification, verify via the actual OS process tree (not just one `tasklist`/`ps` snapshot — retry the check, since a sleeping loop legitimately shows no matching process for stretches of its sleep interval). If a relaunch already happened, explicitly check for more than one live process descending from the same script before assuming there's only one. |
| Oracle Always Free compute can only be created in the tenancy's home region | Attempted to subscribe the existing `eu-zurich-1`-home-region tenancy to an additional region (Frankfurt) to route around the capacity shortage; hit "exceeded maximum number of regions allowed for your tenancy." Turned out to be moot regardless — Oracle's own docs confirm Always Free compute instances must be created in the home region only, so successfully adding a region would not have helped anyway. | advisory | A brand-new tenancy (new email, home region chosen at signup) is the only free-tier path to a different region; subscribing an existing tenancy to more regions does not unlock Always Free compute elsewhere. Not pursued this session — see hosting pivot below. |
| VPS "hourly billing" is not usage-metered billing | Initially worried that Netcup's hourly-billing option could produce an AWS-style surprise bill from CPU load or traffic spikes ("server lag") — verified via netcup's own FAQ and community docs it is not: the hourly rate is a fixed monthly price ÷ 720, independent of actual CPU/RAM usage, and traffic overage throttles bandwidth rather than billing for it. | advisory | When evaluating hosting options against the standing "no AWS-style bill risk" constraint, distinguish fixed-spec-box billing (Hetzner/Netcup-style, prorated by time, not usage) from genuinely metered billing (AWS EC2/data-transfer-style) — the former does not carry the risk being screened for even when marketed as "hourly." |
| OCI console's "Create new virtual cloud network" leaves orphaned networking on a failed launch | Each failed manual "Create" click (instance launch failing on capacity) still fully created a VCN + public subnet + internet gateway before the launch itself failed — repeated retries accumulated 9 duplicate/incomplete VCNs across ~15 manual attempts. | advisory | Use one fixed, already-verified subnet across all retry attempts (the CLI poller does this structurally) instead of repeatedly going through the console's quick-create-VCN flow. Now moot if Oracle is not the deploy target, but the poller (still running as a background bet) still benefits from this. |
| System's default Python has no PyYAML wheels | This machine's default Python (3.15-rc via `py -0p`, and also 3.14) has no prebuilt PyYAML wheel on Windows, and MSVC Build Tools aren't installed to compile from source — breaks any `pip install` needing PyYAML (including the OCI CLI installer's own bundled-venv approach). | advisory | Install a stable, well-supported Python (3.12 via `winget install Python.Python.3.12`) and build any Python-CLI-tool venv against that explicitly, not whatever `python3`/`py -0p`'s default entry resolves to. |
| Manually `Start-Process`-detached processes get killed by this session's sandbox | Tried launching the retry poller as a fully OS-detached PowerShell process (`Start-Process -WindowStyle Hidden`) so it would outlive any single tool call. It never even wrote its first log line — the sandbox reaps child processes when the spawning tool call's own process tree is cleaned up. | advisory | Use the harness's own `run_in_background: true` Bash mechanism for anything that must survive past one tool call. |
| `oci` CLI transient 401 `NotAuthenticated` right after adding an API key | First `oci iam region list` call after writing `~/.oci/config` failed with `NotAuthenticated` even though the signed request was structurally correct. Retrying ~30s later succeeded with no changes. | advisory | Treat an immediate post-setup 401 as propagation delay, not a config error — retry once or twice before re-checking the config file itself. |
