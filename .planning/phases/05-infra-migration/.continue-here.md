## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| OCI console's "Create new virtual cloud network" leaves orphaned networking on a failed launch | Each failed manual "Create" click (instance launch failing on capacity) still fully created a VCN + public subnet + internet gateway before the launch itself failed — repeated retries accumulated 9 duplicate/incomplete VCNs across ~15 manual attempts. | advisory | Use one fixed, already-verified subnet across all retry attempts (the CLI poller does this structurally) instead of repeatedly going through the console's quick-create-VCN flow. |
| System's default Python has no PyYAML wheels | This machine's default Python (3.15-rc via `py -0p`, and also 3.14) has no prebuilt PyYAML wheel on Windows, and MSVC Build Tools aren't installed to compile from source — breaks any `pip install` needing PyYAML (including the OCI CLI installer's own bundled-venv approach). | advisory | Install a stable, well-supported Python (3.12 via `winget install Python.Python.3.12`) and build any Python-CLI-tool venv against that explicitly, not whatever `python3`/`py -0p`'s default entry resolves to. |
| Manually `Start-Process`-detached processes get killed by this session's sandbox | Tried launching the retry poller as a fully OS-detached PowerShell process (`Start-Process -WindowStyle Hidden`) so it would outlive any single tool call. It never even wrote its first log line — the sandbox reaps child processes when the spawning tool call's own process tree is cleaned up. | advisory | Use the harness's own `run_in_background: true` Bash mechanism for anything that must survive past one tool call — confirmed this actually works (the OCI CLI install and the eventual poller both ran correctly this way, well past their own inline timeouts). |
| `oci` CLI transient 401 `NotAuthenticated` right after adding an API key | First `oci iam region list` call after writing `~/.oci/config` failed with `NotAuthenticated` even though the signed request (fingerprint, both OCIDs, signature) was structurally correct and the key file's own computed fingerprint matched exactly. Retrying ~30s later succeeded with no changes. | advisory | Treat an immediate post-setup 401 as propagation delay, not a config error — retry once or twice before re-checking the config file itself. The poller's own error classification already gives `NotAuthenticated` a 5-consecutive-strike tolerance before treating it as a real credential problem. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
