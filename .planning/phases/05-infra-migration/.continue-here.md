## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Worktree isolation torn down between agent turns | The first attempt at plan 05-04 dispatched a `gsd-executor` with `isolation="worktree"`. That call returned a human-action checkpoint (read-only, no edits/commits made). Continuing it via a `SendMessage`-based resume ran the agent fresh with no worktree bound at all — the harness had torn the worktree down once the first call returned, and `SendMessage`/resume does not recreate or rebind it. `git worktree list` showed only the main checkout; `.git/worktrees/` didn't exist; no `agent-*` branch existed anywhere. Zero work was lost only because both turns were 100% read-only. | blocking | Dispatch plan 05-04's executor **sequentially** (no `isolation="worktree"` in the `Agent()` call) — normal commits directly on the main checkout, with hooks. This plan is the sole plan in its wave (no parallel-plan collision risk to protect against) and needs many rounds of human back-and-forth across separate turns, which is exactly the shape worktree isolation doesn't survive. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
