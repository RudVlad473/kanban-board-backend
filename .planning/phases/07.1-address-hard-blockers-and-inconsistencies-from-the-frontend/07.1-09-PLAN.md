## Non-obvious trade-offs

- **The scan may reopen this phase.** A high-severity finding in code this phase just wrote is a
  legitimate reason to fix it here rather than defer it — that is what "triaged and either fixed or
  explicitly deferred" means. Task 2 is deliberately open-ended in scope for that reason, and its
  size cannot be estimated in advance.
- **Diagram accuracy over diagram beauty.** These diagrams are being written for a frontend hand-off,
  so a diagram that is pretty but wrong is worse than no diagram. Task 3 requires each participant
  and each message to be traced to a named source file rather than drawn from memory of the codebase.
- **Ordering is a hard constraint, not a preference.** D-24 and D-26 both state it explicitly, and
  the fourth diagram literally cannot be drawn correctly before plans 07.1-01 and 07.1-03 land — the
  401/403/400/409 split it documents does not exist until then.
</tradeoffs>
