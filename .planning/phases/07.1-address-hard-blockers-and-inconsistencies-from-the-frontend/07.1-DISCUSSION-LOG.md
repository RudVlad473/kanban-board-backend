## Error envelope shape

| Question | Options | Selected |
|---|---|---|
| Converged JSON error shape? | Custom minimal envelope / **Spring's RFC 7807 ProblemDetail** | ProblemDetail |
| Nest field-validation errors? | **Nest under "errors" field** / Keep as separate top-level shape | Nested |
| Add a machine-readable code? | **Yes, per exception type** / No, status+message enough | Yes |
| Same shape for true-unauthenticated (filter-chain) case? | **Yes, wire an AuthenticationEntryPoint** / No, leave Spring Security default | Yes |

**Notes:** Landed on ProblemDetail specifically because it's a standard, framework-supported shape that still allows custom extension properties (`errors`, `code`) without inventing a bespoke envelope.
