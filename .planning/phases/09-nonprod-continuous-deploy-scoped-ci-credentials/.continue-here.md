# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: SSH host key fingerprint algorithm mismatch — `appleboy/ssh-action`'s Go SSH client does not negotiate the same host key type a normal `ssh` client would; ED25519 was independently verified correct three separate ways and still failed live, because the client library's default host-key preference (`golang/go#51168`) ranks ECDSA above ED25519 — before touching `NETCUP_HOST_FINGERPRINT` again for any reason, use the VM's ECDSA fingerprint (`ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub`), not whichever key type `ssh -vv` naturally negotiates for a normal client.
- [ ] CONSTRAINT: A plan's `files_modified` list is not the full set of files its live behavior depends on — `docker-compose.nonprod.yml` was in 09-01's `<read_first>` list but not its `files_modified` list, so the plan's author (reasonably) never told the executor to check whether that file's hardcoded image-repository name needed updating too. Before trusting any plan's declared scope as complete, check whether a file it only *reads* actually needs a corresponding write.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Trusting a write-only secret store without falsifying the claim | Assumed "I sent the correct value to `gh secret set`" implied "GitHub has the correct value" — no way to read a GitHub secret back to check. | advisory | Use a hash-comparison probe (a temporary `workflow_dispatch` job printing `sha256sum` of the secret, never the secret itself) to verify what's actually stored, whenever a write-only credential store's content is in question. |
| Assuming the naturally-negotiated SSH host key type is what a Go SSH client library will check | A normal `ssh -vv` connection negotiated ED25519 (matching the client's own preference order); `appleboy/ssh-action`'s Go client negotiated ECDSA instead, because Go's `golang.org/x/crypto/ssh` default `HostKeyAlgorithms` list ranks ECDSA before ED25519 (`golang/go#51168`). | blocking | When pinning a host key fingerprint for a Go-SSH-client-based GitHub Action, test with the actual action (a harmless read-only command like `whoami`) rather than assuming a normal OpenSSH client's negotiated key type applies. |
| Watching the wrong CI workflow after a push | `deploy.yml` and `secret-scan.yml` both trigger on every push to `master`; watched `secret-scan.yml`'s run once by mistake and reported a false "success" for the deploy before catching it. | advisory | After any push, explicitly filter `gh run list` by workflow `name`, not just by branch/recency, before watching or reporting a run's conclusion. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
