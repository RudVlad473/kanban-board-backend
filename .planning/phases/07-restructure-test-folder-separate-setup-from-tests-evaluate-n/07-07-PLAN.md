<tradeoffs>
## Approach considered A — rename the twelve downgraded classes to drop the E2ETest suffix, and retune the fastTest filter in the same phase

## Approach considered B — change nothing about naming or the build script; file the decision — CHOSEN

## Approach considered C — say nothing about it

| Approach | Pros / Cons | Why picked / rejected |
|----------|-------------|-----------------------|
| A — rename now | Pro: the suffix would finally mean something again, and twelve now-cheap classes would join the pre-commit gate. Con: it silently changes what every future commit runs locally — twelve additional container-backed classes on every `git commit` — which is a developer-workflow change no decision in CONTEXT.md authorises. It also lands a twelve-file rename on top of an already ~3,700-line refactor, making the phase's real diff harder to review | Rejected for this phase |
| B — file the decision | Pro: the finding is captured with the evidence fresh, the phase stays reviewable, and the naming and filter questions get decided together rather than one forcing the other. Con: the suffix stays temporarily misleading on twelve classes | **Picked** |
| C — stay silent | Pro: nothing. Con: the build script's comment is now imprecise and nobody would know why | Rejected |

**Non-obvious trade-offs:**
- **The suffix and the pre-commit gate are coupled through a string match, and only one of them was
  ever documented.** `fastTest` excludes `*E2ETest` by class-name pattern, and the pre-commit hook
  runs `fastTest`. So the suffix is not merely descriptive — it is load-bearing build configuration.
  Renaming a class changes what runs before every commit. That coupling is exactly why the rename is a
  decision and not a tidy-up.
- **The build script's stated rationale is already stale, independently of this phase.** It describes
  `fastTest` as excluding "Testcontainers-backed" classes, but since H2 was dropped every test is
  Testcontainers-backed — the included controller tests start PostgreSQL too. What the filter actually
  excludes today is real-socket and real-Kafka classes. After this phase it excludes twelve classes
  that are neither. Worth correcting when the decision is made, not before.
- **The suite should get faster, and the measurement is worth taking.** Twelve classes stop starting an
  embedded servlet container. The last recorded like-for-like full-suite figures on this machine are
  291s and 295s for 210 tests (Phase 04.2). Record the new figure — but treat it as an observation, not
  a success criterion; a slower run is not a failure, only a fact worth writing down.
- **A shrinking test count is a defect, not an efficiency.** The merge preserved every test method and
  the two deleted classes held none, so the total must not drop. If it did, a nested group was lost in
  the merge.
</tradeoffs>
