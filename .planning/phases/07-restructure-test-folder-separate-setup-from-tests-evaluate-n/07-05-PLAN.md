<objective>
Downgrade the full-board read class and the subtask optimistic-locking class from the real-socket
RestAssured tier to the in-process MockMvc tier (D-03, verdict-table rows 10 and 13).

Purpose: the full-board read asserts nothing but status codes and JSON body shape — both faithfully
reproduced by MockMvc — and the subtask locking class is a sequential write-then-write conflict flow.
Neither needs a real socket.

This plan is also where the real-socket tier's remaining occupant becomes visible: once these two
classes move, `BoardCreationE2ETest` is the only class left extending the real-HTTP fixture base, kept
deliberately because its concurrent-create group races two genuinely concurrent threads against a
database unique constraint. Leave it alone.

Output: two converted files, same coverage, one tier cheaper.

Zero production-code changes: `src/main/java` is untouched by this plan.

Scope note: D-02's conditional Board and Subtask merge candidates are explicitly OUT of scope and
deferred entirely. Convert in place; do not merge, rename or move.
</objective>

<tradeoffs>
## Approach considered A — assert the full-board document by deserialising into the response DTO

## Approach considered B — preserve whatever assertion style each source test already uses — CHOSEN

## Approach considered C — also downgrade the non-concurrent groups of BoardCreationE2ETest by splitting the file

| Approach | Pros / Cons | Why picked / rejected |
|----------|-------------|-----------------------|
| A — normalise to DTO deserialisation | Pro: uniform, type-safe assertions across the file. Con: changes strictness in ways that are easy to get wrong — a DTO round trip silently tolerates unexpected extra fields that a strict JSON comparison would catch, so "still passes" would no longer mean "still proves the same thing" | Rejected. Preserving strictness matters more than uniformity in a refactor |
| B — preserve existing assertion style | Pro: the diff shows only the dispatch mechanism changing, so a reviewer can see at a glance that coverage is untouched. Con: the file keeps whatever mix of styles it already had | **Picked** |
| C — split the board-creation file | Pro: would move four more nested groups to the cheap tier. Con: RESEARCH.md offers this only as an option, splitting a file is a merge-shaped change that this phase's scoping decision defers, and the concurrency question behind that class (Assumption A1) was deliberately left unresolved | Rejected. Explicitly out of scope; the class stays whole and stays on the real-socket tier |

**Non-obvious trade-offs:**
- **JSON strictness is the whole point of the full-board class.** That class exists because the nested
  read replaced a four-round-trip fan-out; its value is that the nested document and the flat
  endpoints agree. Any loosening of a body comparison during conversion silently removes that value
  while keeping the test green.
- **MockMvc reproduces response bodies and headers faithfully; that is why this downgrade is safe.**
  Status codes, headers including `Location`, JSON body shape and `Set-Cookie` values are all
  reproduced. What MockMvc does *not* provide is genuinely concurrent multi-threaded dispatch — which
  is exactly and only why `BoardCreationE2ETest` is excluded.
- **The real-HTTP fixture base ends this phase with one subclass.** That is an expected outcome, not a
  leftover. Do not delete the base class, and do not "tidy up" by folding it into its last subclass —
  it documents the real-socket tier and is the landing place for any future socket-level test.
- **Query-count assertions, if present, are sensitive to the persistence context.** The full-board read
  is about round-trip count. If this class asserts on query counts, that helper reads Hibernate's
  prepared-statement counter and must not be moved relative to the request it wraps, and no
  test-managed transaction may be introduced around it.
</tradeoffs>
