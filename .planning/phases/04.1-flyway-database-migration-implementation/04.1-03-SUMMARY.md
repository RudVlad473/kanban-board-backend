# Phase 04.1 Plan 03: ddl-auto=validate cutover Summary

**Flipped Hibernate to `ddl-auto=validate` in both `application.properties` and the docker-compose `app` service (closing RESEARCH.md's Open Question 1 by making the local stack actually exercise deploy-equivalent behavior), and marked the three manual DDL bridge scripts this phase replaces as superseded, with their replacement migrations named and their original bodies preserved as provenance.**

## Performance

- **Duration:** ~25 min for the two automated tasks (including two pre-commit hook runs, one of which needed a `./gradlew --stop` retry for a stale-daemon file lock)
- **Tasks:** 2 of 3 (Task 3 is a blocking human-verify checkpoint, not yet run)
- **Files modified:** 6

## Accomplishments

- `spring.jpa.hibernate.ddl-auto=validate` added to `application.properties` under the `# === hibernate ===` banner, with an inline comment stating the division of labor between Flyway (creates/alters) and this setting (only validates).
- `docker-compose.yml`'s `app` service `SPRING_JPA_HIBERNATE_DDL_AUTO` changed from `update` to `validate`, with an inline comment explaining why (env vars outrank `application.properties` in Spring Boot's property precedence, so leaving the old value would silently defeat the cutover locally).
- `application-test.properties` untouched — `ddl-auto=create-drop` and `spring.flyway.enabled=false` both still present (D-04).
- All three manual DDL bridge scripts (`02-optimistic-locking-ddl.sql`, `03-activity-log-ddl.sql`, `04-password-hash-not-null-ddl.sql`) now carry a superseded-by header naming the exact Flyway migration that replaced each (`V2__add_optimistic_locking_version_columns.sql`, `V3__add_activity_log.sql`, `V4__add_password_hash_not_null.sql`); original bodies preserved verbatim below each header.
- `docs/plans/backend-modernization/03-flyway-openapi.md` now carries a dated status note: Flyway half shipped in GSD Phase 04.1, OpenAPI half remains open, plus the INFRA-06 (Neon DDL check → Flyway migrate/validate) and `rehearseHistoricalSchemas` (non-empty-schema trap against an auto-alter-built database) heads-ups for whoever resumes Phase 5.
